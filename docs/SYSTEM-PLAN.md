# 高校辅导员智慧管理系统方案（SmartCounselor / 辅智通）

版本：正式架构稿 v2.1（外壳与工作空间分离 + 智慧管理赋能 + 本地 CPU 小模型协同）  
日期：2026-11-05  
系统名称：**高校辅导员智慧管理系统**  
产品代号 / 中文简称：**辅智通**（英文名 / GitHub 仓库建议名：`smart-counselor` 或 `SmartCounselor`）  
目标环境：Windows 桌面端，纯离线本地运行，**软件外壳与独立工作账套（Workspace/Data Suite）彻底分离**，可作为标准化智慧办公软件分发给不同高校辅导员使用。

---

## 1. 目标与核心定位

构建一个**轻量、纯离线、开箱即用、可分发**的高校辅导员智慧管理系统。界面借鉴 Baserow 的表格、筛选视图与全息详情侧栏，数据管理采用**软件外壳与独立工作账套分离机制（App Shell 与 Workspace / Data Suite 分离）**。

### 1.1 已确认的业务与架构范围

- **程序与数据分离**：软件本体（App Shell）不含任何个人或特定学校硬编码数据；用户首次启动可“新建工作账套（Workspace）”或“打开已有账套”，支持同一软件管理多个年级/班级工作账套，支持直接分发给其他辅导员安装使用。
- **学生底座与 14 个四字业务板块**：覆盖学生基本信息、肖像照，以及思政、党团、日常、奖惩、学风、心理、就业、资助、安全、网络、应急、实务、成长全周期记录。
- **双模式附件管理**：图片、视频、音频和文档全部独立于数据库存储。支持**“托管归档模式（默认自动复制整理到账套目录）”**与**“原地链接模式（仅登记外部已有大目录路径）”**。
- **灵活导入与导出**：支持国内高校复杂多行表头 Excel 导入映射；支持按学生、字段、记录类别和时间范围导出 Excel、单文件便携 HTML/PDF 档案卡，并自动收集关联附件打包。
- **分级加密与安全恢复**：SQLCipher 全库加密 + 随机数据密钥（DEK）+ 独立恢复密钥；高敏附件支持内置透明加密保险箱，大型附件支持外部加密卷离线状态识别。
- **纯本地 CPU 小模型 AI 协同（智慧引擎）**：基于 `llama.cpp` / GGUF 量化小模型（如 Qwen2.5-1.5B/3B），在普通轻薄本 CPU 上纯离线完成谈话纪要润色、结构化字段提取、评语草稿生成与导出脱敏检查，**零网络上传**。

## 2. 核心架构设计

### 2.1 程序外壳与工作账套（Workspace）分离架构

系统严格区分**“无状态程序外壳（Application）”**与**“用户业务工作账套（Workspace）”**：

```text
[程序安装目录 / 便携运行目录] (可分发给任意用户)
SmartCounselor_App/
  ├── SmartCounselor.exe           # Tauri 2.0 轻量主程序 (~15MB)
  └── engines/                     # 可选：本地 AI 推理组件 (llama-server.exe, 按需加载)

[用户自定义业务工作账套目录] (可放在 D 盘、移动硬盘或加密卷，支持建多个账套)
D:\CounselorData\2026级计算机系工作账套.scdata/
  ├── workspace.json               # 账套元数据（版本、账套名称、加密参数、外部根目录映射表）
  ├── database/
  │   └── main.db                  # SQLCipher 加密主数据库（结构化表 + 字典配置 + 富文本）
  ├── managed_files/               # 托管归档附件区（默认根编号 @workspace）
  │   └── 20260001/
  │       ├── 肖像/
  │       ├── 日常管理/
  │       └── 资助育人/
  ├── secure_box/                  # 内置 AES-256-GCM 透明加密附件区（心理/处分高敏材料，根编号 @secure）
  └── backups/                     # 本地一致性备份快照
```

1. **分发友好**：把 `SmartCounselor.exe` 发给任何同事，对方打开后通过向导在自己电脑上选择目录创建新账套、设置自己的主密码、导入自己的 Excel 即可使用。
2. **多账套切换**：辅导员可在左上角切换“2022级毕业生归档账套”、“2026级在读账套”或“演示测试账套”。

### 2.2 附件路径定位机制

附件路径采用 **`存储根目录编号 + 相对路径`**：

- **内置托管根目录（`@workspace`）**：指向当前工作账套下的 `managed_files/`，开箱即用，随工作账套文件夹整体移动无需任何重配置。
- **内置加密保险箱（`@secure`）**：指向当前工作账套下的 `secure_box/`，文件以 AES-256-GCM 加密存放，解锁数据库后在内存/受控流中解密预览。
- **外部自定义根目录（`root_01`, `root_02`...）**：指向电脑其他盘符或移动硬盘的历史资料目录（如 `E:\历年学工视频库`）。整体搬家时只需修改根目录映射路径。

## 3. 用户界面与导航分层

### 3.1 左侧三层式导航架构（解决“查人”与“查事”的主次关系）

为避免 14 个板块平铺导致的认知负荷，左侧导航按辅导员高频思维逻辑划分为三层，全部保持四字规范命名：

1. **【第一层：档案底座（以人/空间为中心，占日常 80% 检索）】**
   - **基本信息**（学生总库：一行一人，Baserow 风格多视图表格，支持筛选、字段显隐、分组）
   - **宿舍视图**（空间底座：按“楼栋 → 寝室 → 床位”卡片网格展示，支持查寝登记、空床位查看与调宿）
2. **【第二层：专项台账（以业务事件为中心，11 个关联学生板块，一行一事）】**
   - **思政教育**、**党团建设**、**日常管理**、**行为奖惩**、**学风建设**、**心理健康**（带锁独立访问）、**就业指导**、**资助育人**、**安全管理**、**网络育人**、**应急处突**。
   - *注：导航支持折叠分组、常用置顶和隐藏低频板块。*
3. **【第三层：个人案头与系统工具】**
   - 个人积累：**工作实务**、**专业成长**（不强制绑定学生，辅导员个人文档与待办库）。
   - 公共工具：**附件管理**、**数据导出**、**数据备份**、**目录管理**、**本地智助（AI）**。

### 3.2 学生全息详情侧栏

在“基本信息”或“宿舍视图”点击任意学生，右侧滑出全息详情侧栏：
- **顶部卡片**：肖像照、姓名、学号、班级、宿舍床位、重点标签、快捷联系方式（身份证与家长电话默认掩码，点击显隐）。
- **中部视图切换**：
  - **按模块聚合 Tab**：分别查看该生的日常请假、成绩单、奖助贷、谈心记录等。
  - **全景时间线（Timeline）**：按发生时间倒序串联该生入学以来的所有事件（心理健康记录默认隔离折叠，需二次确认解锁后才可混入查看）。
- **快速追加**：侧栏内一键新增任意板块记录，自动绑定当前学生。

## 4. 轻量化数据模型（核心关系表 + 强类型 JSON 收敛）

### 4.1 设计原则：拒绝表膨胀，兼顾结构化查询与演进灵活性

原方案若为 14 个板块分别建立专用物理明细表，会产生 35+ 张表，严重拖累单机软件的开发与维护。v2.0 采用 **“10 张核心关系表 + 受控 Schema 的 `payload_json` + SQLite 虚拟生成列索引（Generated Columns）”** 架构：

### 4.2 核心物理表清单（共 10 张）

| 序号 | 表名 | 核心职责与设计说明 |
| :---: | :--- | :--- |
| 1 | `students` | **学生主表**：内部 UUID 主键、`student_no`（学号唯一索引）、姓名、性别、班级、年级、专业、宿舍楼栋/房间/床号、在校状态、政治面貌、困难等级、肖像附件 ID、`extra_json`（自定义扩展列）。 |
| 2 | `student_contacts` | **家庭与紧急联系人表**：学生 ID、姓名、关系、电话、职业/地址、是否主要联系人。 |
| 3 | `records` | **全业务公共记录主表**：记录 ID、`module`（14板块编码）、`sub_type`（子类型）、标题、发生时间、结束时间、状态、敏感级别、富文本正文（Tiptap JSON）、**`payload_json`（各模块专用结构化数据）**、加上关键生成列（如 `amount_cents` 金额分、`academic_term` 学期、`approval_status` 办理状态）。 |
| 4 | `record_students` | **记录—学生参与关联表**：支持一人多记录与一事多学生（如班会、宿舍违纪、突发事件）。含 `student_id`、`record_id`、`role`（主当事人/参与人）、`personal_summary`（仅属于该生的独立陈述或处理结果，单人导出时严格隔离他人信息）、`attendance_status`（出勤/时长/学分）。 |
| 5 | `record_updates` | **过程跟进与状态变更流**：记录 ID、操作时间、动作类型（提交/审批/跟进/解除/验收/结案）、状态变化、说明文本。确保处分解除、隐患整改、党员发展阶段等全程可追溯，不直接覆盖历史。 |
| 6 | `grade_rows` | **高频学业成绩明细表**：因每学期每人多门课行数大、统计频繁，独立建表。含学生 ID、学年学期、课程名、课程性质、学分、原始成绩（文本保留等级或分数）、绩点、是否补考/重修、导入批次号。 |
| 7 | `work_notes` | **工作实务与专业成长文档表**：不强制绑学生的文档（工作日志、SOP、应急预案版本、培训研修、通知存档、案例复盘、待办事项）。 |
| 8 | `storage_roots` & `attachments` | **存储根目录与附件索引表**：稳定附件 ID、根目录 ID（`@vault` / `@secure` / 外部根）、相对路径、显示名称、扩展名、字节大小、SHA-256 哈希、可用状态、加密标记。 |
| 9 | `attachment_links` | **附件多对多引用表**：关联目标类型（学生肖像/业务记录/个人文档）、目标 ID、附件 ID、敏感级别、是否多人共用材料（控制单人导出脱敏边界）。 |
| 10 | `system_meta` | **系统配置、字典与视图表**：合并保存可配置业务字典（政治面貌、处分等级、资助项目、党员阶段）、扩展字段定义（`field_definitions`）、保存的筛选视图（`saved_views`）及导入导出操作日志。 |

### 4.3 `records.payload_json` 的强类型约束机制

不同业务板块的专用字段（如请假起止与销假时间、资助认定金额与实发批次、处分文号与期限、就业意向与落实去向、心理普测等级与转介记录）通过应用层（Rust Struct + TypeScript Interface）定义严格的模块 Schema：
- **金额规范**：统一以“分”的整数（`amount_cents`）存储，区分“认定金额”、“应发金额”、“实发金额”三个明确枚举子类型，统计时绝不混加。
- **处分与阶段规范**：到期时间仅触发“待解除提醒”，必须追加一条类型为“解除决定”的 `record_updates` 后才变更为已解除。

## 5. 双模式附件管理与目录防丢机制

### 5.1 登记附件的两种模式（解决碎片文件易丢失痛点）

用户添加文件（拖拽或选择文件）时，系统提供清晰开关：

1. **模式 A：归档入库模式（默认推荐，适合日常碎片文件）**
   - 当用户从微信文件夹、桌面或下载目录拖入假条照片、谈话截图、证书文档时，系统自动将其**复制到当前档案库的 `@vault/学号/板块名称/` 目录下**，按规范命名并登记相对路径。
   - **优势**：哪怕用户随后清空了微信缓存或桌面，档案库内的附件依然完好无损；整个档案库文件夹拷贝到新电脑即可直接使用。
2. **模式 B：原地链接模式（适合已整理好的大型历史资料库）**
   - 用户选择已登记的外部存储根目录下的文件（如移动硬盘中的大容量活动视频、历年扫描件归档目录），系统**只登记相对路径，不复制文件**。

### 5.2 根目录状态识别与地址迁移

- **区分“卷未挂载”与“文件丢失”**：如果外部根目录位于移动硬盘或第三方加密卷（如 VeraCrypt/BitLocker），当该盘符未连接或未解锁时，系统将整个根目录状态标为 **`离线/待挂载 (Offline)`**，友好提示用户连接或解锁磁盘，**绝不将下属几千个附件误标为“文件丢失”**。
- **地址迁移与重命名**：保留原方案的“更新根目录地址映射”与“软件带进度复制迁移”能力；默认修改显示名称，物理重命名时自动检测冲突并同步全部引用。

## 6. 高校复杂 Excel 导入与多维导出引擎

### 6.1 针对高校非标 Excel 的强化导入向导

流程：**选择文件与工作表 → 指定表头行号与数据起止行 → 字段映射与匹配规则 → 差异与错误预览 → 事务写入与结果清单**。

- **多行复杂表头适配**：支持预览表格前 15 行，允许用户点击指定第 N 行作为真实表头（自动忽略前几行的“XX学院统计表”合并大标题与填表说明），并支持过滤末尾的“合计/制表人”非数据行。
- **防误抹除与类型保护**：学号、身份证、手机号、银行卡号强制按纯文本解析保留前导零；空单元格默认不清空库内已有值；同名学生强制以学号区分，学号冲突或缺失进入人工确认队列。

### 6.2 单人及批量导出（增加单文件便携报告）

- **导出范围与敏感拦截**：
  - 心理健康、家庭困难详情、违纪处分、身份证号默认排除在常规导出之外，需显式勾选并通过二次确认。
  - 多人共同事件（如宿舍通报、打架处分）在单人导出时，**仅导出事件公共摘要与该生本人的 `personal_summary`**，严禁带出其他涉事学生姓名与材料；多人共用的未脱敏附件默认拦截并提示人工处理。
- **三种导出产物形态**：
  1. **自定义字段汇总 Excel (`学生清单.xlsx`)**：按当前筛选视图和勾选列生成标准表格。
  2. **单人全息成长档案卡（便携单文件 HTML / 一键打印 PDF）**：将学生肖像、基础资料表、所选板块的时间线记录排成标准公文样式的报告，支持直接通过内置 WebView 打印输出为 **单文件 PDF**（解决外部图片脱离文件夹裂开的问题，方便打印签字或汇报）。
  3. **完整资料交付包 (`导出包.zip`)**：含汇总 Excel、单人独立目录、HTML 档案、提取的关联附件副本及 `文件清单.json` 校验表，流式打包不占内存。

## 7. 本地 CPU 小模型 AI 协同方案（纯离线、零外传）

### 7.1 架构原则：插件化解耦、纯 CPU 流畅运行、严守安全边界

1. **外壳轻量化解耦**：主程序安装包不捆绑数 GB 的模型文件。AI 模块采用 **可插拔本地推理后端**，支持：
   - **内置模式**：通过轻量级 `llama.cpp` (`llama-server` CPU 引擎，支持 AVX2 指令集加速) 加载用户放入本地的 `.gguf` 模型文件。
   - **桥接模式**：若用户电脑已安装 `Ollama` 或 `LM Studio`，可直接连接本地回环地址 `http://127.0.0.1:11434`。
   - **网络硬隔离**：推理请求仅允许发往 `127.0.0.1` / `localhost`，软件底层禁用任何外部公网 API 调用。
2. **推荐 CPU 模型配置（普通轻薄办公本无独显即可流畅运行）**：
   - **极速档（推荐 8GB~16GB 内存笔记本）**：`Qwen2.5-1.5B-Instruct-Q4_K_M.gguf`（模型体积仅 **~1.0 GB**，CPU 生成速度约 25~40 字/秒）。
   - **均衡档（推荐 16GB+ 内存电脑）**：`Qwen2.5-3B-Instruct-Q4_K_M.gguf`（模型体积 **~2.0 GB**，公文润色与信息提取极佳，CPU 速度约 15~25 字/秒）。

### 7.2 辅导员五大本地 AI 实用场景

| 场景名称 | 触发位置 | 实际作用 |
| :--- | :--- | :--- |
| **1. 谈心纪要公文化润色** | 思政/日常/就业等记录编辑器 | 输入几句随手记的碎片化口语要点，一键扩写整理为条理清晰、用词规范的辅导员谈心谈话纪要。 |
| **2. 记录要素自动提取** | 新增记录侧栏 | 从粘贴的聊天记录或长段叙述中，自动提取建议的“记录标题、事件分类、发生时间、后续跟进待办事项”并填入表单草稿。 |
| **3. 学生综合评语/小结生成** | 学生详情侧栏 | 自动汇总该生选定学期内的成绩、获奖、担任职务、活动出勤，生成操行评定、入党考察或奖学金推荐意见初稿。 |
| **4. 案例复盘与导出脱敏扫描** | 专业成长 / 数据导出预览 | 在撰写工作案例或导出单人材料前，本地扫描正文是否遗漏未隐去的他人姓名、学号、手机号、宿舍号，高亮提示一键替换为化名（如“张某”）。 |
| **5. 自然语言智能筛选** | 表格顶部搜索框 | 输入“大二绩点低于2.0且本学期请假超过2次的学生”，自动解析为表格的结构化筛选条件组合。 |

> **安全铁律**：本地 AI 的所有输出均为**“待确认草稿”**，必须由辅导员人工审阅点击“采纳”后方可写入数据库；AI **绝不参与**心理健康风险自动定级或处分结论判定。

## 8. 加密、密码恢复与备份体系

1. **数据库加密（SQLCipher）**：
   - 采用 AES-256 全库加密。底层使用随机生成的 256 位数据主密钥（DEK）；用户的**登录密码**与系统初始化生成的**独立恢复密钥（Recovery Key）**分别通过 Argon2id/PBKDF2 派生密钥来加密保护 DEK。
   - 修改密码只需重新封装 DEK，无需全库重写；忘记登录密码时凭打印/离线保存的恢复密钥即可无损重置。
2. **附件分级保护**：
   - **核心高敏附件（心理、处分等）**：存入工作账套 `@secure` 目录，由软件直接使用 DEK 进行 AES-256-GCM 文件级加密，无需第三方软件即可实现“锁账套即锁文件”。
   - **常规大体积附件**：存入 `@workspace` 或外部加密卷（如 BitLocker / VeraCrypt），界面清晰标识各存储根目录的加密保护状态。
3. **一致性备份与恢复演练**：
   - 支持**仅备份加密数据库**（秒级完成）与**全量打包加密备份（`.scbak`）**。
   - 提供“沙盒恢复校验”功能：在不覆盖当前账套的前提下，验证备份包能否正常解密并核对记录数与附件哈希。

## 9. 技术栈与 GitHub 云端自动化构建（本地零编译负担）

为实现“极致轻量（安装包 ~15MB）、本地免配重型 C++ 编译环境、跨机器分发”，确定以下工程方案：

| 层级 | 选定技术方案 | 选择理由 |
| :--- | :--- | :--- |
| **桌面宿主外壳** | **Tauri 2.0 (Rust)** | 调用系统原生 Edge WebView2，安装包仅 ~15MB，内存占用极低，原生支持程序与账套数据分离。 |
| **前端界面** | **Vue 3 + TypeScript + Tailwind CSS** | 响应迅速，易于构建 Baserow 风格高性能虚拟滚动表格与全息侧栏。 |
| **表格与富文本** | **TanStack Table (或 VxeTable) + Tiptap** | 完美支持列冻结、多维筛选、字段显隐、JSON 结构化富文本与本地图片 ID 引用。 |
| **加密数据库** | **rusqlite (`bundled-sqlcipher`)** | 编译时静态内嵌 SQLCipher，在 Windows 下无需用户安装任何外部 DLL。 |
| **Excel 与压缩** | **SheetJS / ExcelJS + Rust `zip` 流式库** | 兼顾前端多行表头可视化预览与后端大附件流式打包导出。 |
| **本地 AI 接口** | **OpenAI 兼容本地客户端 (`127.0.0.1`) + Sidecar 管理** | 同时兼容 `llama.cpp` 本地进程与 `Ollama`，不增加主包体积。 |
| **编译与分发** | **GitHub Actions 云端流水线** | 本地仅用 Node.js 开发调试前端；推送到 GitHub 后由云端 `windows-latest` 自动编译 Rust + SQLCipher 并发布 `.exe` 安装包与便携版。 |
