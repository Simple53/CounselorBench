# 本地账套工程第一阶段

## 启动与入口

源码入口为 `index.html`，构建后入口为 `dist/client/index.html`。两者均依赖本地 HTTP 服务，直接双击 HTML 无法运行模块和本地账套接口。

双击工作区根目录或项目内的 `启动工作台.cmd`。也可在项目目录运行 `npm start`。启动器会检查构建是否过期、按需本地构建、启动服务并打开浏览器；已运行时直接打开现有服务，不另建账套。首次安装仍需 Node.js 22+ 和已有项目依赖。

本地地址固定为 `http://127.0.0.1:4173`。关闭服务窗口会结束服务，下次启动需要密码解锁。源码开发可使用 `npm run dev:local`；单独 `npm run dev` 为不带本地接口的静态预览，只能进入演示。

## 账套与文件

默认目录为 `%LOCALAPPDATA%/SmartCounselor/workspaces`，不放在当前 OneDrive 项目目录中。可在启动前通过 `SC_DATA_DIR` 指定根目录；服务器仅管理该根目录中的UUID账套，不接受任意磁盘读写路径。

```text
<UUID>.scdata/
  workspace.json              # 账套名、版本、盐、封装后的数据密钥
  database/state.scenc        # AES-256-GCM 认证加密的业务快照
  managed_files/<UUID>.scenc  # 独立认证加密的附件，文件名及类型在快照内
  backups/previous.scenc      # 上一次业务快照，仍为密文
```

新建账套为空，不含任何演示学生。演示模式保持独立且不保存。业务数据、心理关注、每日简报、字段模板和布局进入加密快照。API密钥不保存。附件上传成功后先落盘，再提交引用；快照以临时文件、fsync及同目录rename替换，不会把二进制塞进结构化数据。中途失败可能遗留未引用的加密文件，不自动清理，避免误删。

重新打开时只读取附件索引，照片按需加载，导出时再读取文件。新增附件单次上传上限100MB，单个快照上限8MB。这是单人账套快照阶段，不用于高频多人大规模查询。

## 密码和恢复

每个账套随机生成32字节数据密钥，随机96位GCM nonce；每次加密使用独立nonce和绑定账套/文件ID的AAD，128位认证标签校验篡改。密码通过Node标准库scrypt（N=32768,r=8,p=1，随机128位盐）派生包装密钥。独立256位随机恢复密钥另行包装同一数据密钥，可在忘记密码时重设密码，不需要重新加密所有附件。

创建后须另行保存恢复密钥。恢复密钥不会以明文存入账套；任何持有它及账套文件的人都能恢复，请与账套分开保管。密码和恢复密钥都丢失时不能找回。重设密码不吊销之前导出的旧备份及其旧密码。

解锁密钥和API会话保存在本地服务内存；手动锁定、进程关闭后不可再通过原会话读取。浏览器会话使用HttpOnly / SameSite=Strict cookie；API同时验证Host、Origin、跨站来源和随机CSRF头，服务只监听127.0.0.1，不提供局域网共享。此阶段没有自动闲置锁定，也不承诺抵抗已登录系统中的恶意软件或内存取证。

## 保存与备份

右上角显示待保存、正在保存、已保存或失败。失败保留待保存快照，可重试；锁定和备份之前强制等待保存完成，失败时不假称成功。关闭/刷新有未保存工作时触发浏览器离开提示。保存采用版本比较及串行队列，另一页面修改后拒绝旧版本覆盖，需要重新解锁载入。

“加密备份”导出可独立恢复的ZIP，只含账套元信息、加密快照及被引用的加密附件，不含明文恢复密钥。恢复方式：停止服务，将ZIP解压到根目录下的对应 `<workspace.json中的id>.scdata` 文件夹中，不覆盖正在使用的账套，再启动并选择该账套解锁。恢复操作由用户明确选择目录；本阶段尚无可视化还原向导。

## 与正式架构的关系

这一阶段是可测试的本地加密存储适配层，**不是SQLCipher数据库，也不是Tauri安装包**。环境未安装Rust工具链；没有擅自下载工具链或模型。下一阶段可让相同的业务状态/附件适配协议接入Tauri命令和SQLCipher关系表，保留独立账套和数据密钥模型，通过显式迁移导入旧快照。

尚未实现：本地目录选择器、外部链接文件自动读取、物理迁移/重命名、后台垃圾回收、完整审计策略与设备安全认证。外部链接依旧只登记，不能读取时在导出清单中报告缺失。高敏台账内容不进入普通留痕、搜索和导出；当前单一账套密码不是心理模块独立权限系统。

参考：[Node.js Crypto](https://nodejs.org/docs/latest-v22.x/api/crypto.html)、[Vite file协议说明](https://v6.vite.dev/guide/troubleshooting.html)。
